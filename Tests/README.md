# Tests

This folder contains everything that is used to verify Moira. All programs are
built by CMake (`cmake -B build && cmake --build build`) and by the Xcode project.
`ctest` runs the automated ones.

| Folder | Programs | What it checks |
|--------|----------|----------------|
| `Unit/` | `unit` | All unit tests in one [doctest](https://github.com/doctest/doctest) executable: FPU arithmetic and formats, FPU and MMU instruction level tests, bus error frames of the 68000, the debugger (breakpoints, watchpoints, catchpoints, step into/over, software traps, instruction log; on 68000 and 68020), interrupt acknowledgment (autovector levels, masking, NMI edge, user/spurious/uninitialized vectors) CPU space cycles (interrupt and breakpoint acknowledge with FC = 7), and the function code pins (user/supervisor, `MOVES`, exception processing; on 68000, 68010 and 68020), and a comparison of the FPU with UAE's softfloat code. |
| `Smoke/` | `smoke` | Runs the 68000 against the [SingleStepTests](https://github.com/SingleStepTests/m68000) suite (about 260,000 tests recorded from MAME). Checks the final state, the cycle count and every bus access. Needs no arguments and takes a few seconds. |
| `SST/` | `sstmame`, `sstmusashi`, `sstuae`, `exceptionmame`, `exceptionuae`, `retrymoira` | Runs the instructions of the SingleStepTests suite on Moira and on a real reference core (MAME, Musashi or UAE) and compares the results. The prerecorded results are ignored, so every compatibility mode can be checked against its own reference. Compares registers, memory, cycle counts and (if the reference reports them) bus cycles, including the cases that end in an address error. Takes a few seconds. `sstmame` has to give the same result as `smoke`. All three tools reach 100%. `sstuae` does not compare the I/N bit (bit 3) of the address error frame code word, which UAE sets by rules Moira does not model. **Exception tests** (`exceptionmame`, `exceptionuae`, built from the same sources): Differential exception test. Takes the SingleStepTests instructions and compares Moira with a reference CPU when an exception hits in the middle of an instruction: bus errors on every bus access, address errors provoked by perturbing the initial state (odd A7, address registers, extension words, return addresses, ...), and double faults (halted CPU). `exceptionmame` runs Moira in MAME mode against MAME's microcoded 68000, `exceptionuae` runs Moira in UAE mode against WinUAE's cycle-exact 68000. Compared are the stacked frame, registers, status register, cycle count, bus log and written memory. Options: `--only <name>`, `--limit <n>`, `-v <n>`, `--dedupe <n>` (at most n cases per instruction form), `--coverage` (list instruction forms without a case), `--check` (run the reference alone against the SingleStepTests, which verifies the MAME reference CPU), `--ignore ccr,cycles,nbit` (skip condition codes, timing, or the I/N bit of bus error frames), `--tsv <file>`. `exceptionuae` skips cases that fault while a group 1/2 exception is being processed, because UAE and MAME disagree on those frames. `exceptionuae --cpu 68020` runs the same cases against UAE's 68020 core (no timing, bus errors on data accesses only, one per operand access, reaches 100%). Of the 68020 frames only the SR, PC, format word and fault address are compared, because UAE leaves the internal words empty and sets the SSW only partially. In UAE mode Moira copies UAE's register and flag timing at the moment of the fault (predecrement and postincrement of pure writes, condition codes of MOVE and CLR, MOVEM, UNLK, RTE access order). The differences that are known to be defects of UAE are not counted (`UaeCore::knownDifference`): the pipe stages, the PC of address error frames (Moira follows recordings of a real A1200), and the stale PC that JSR stacks when pushing the return address fails. Cases with 68020 full format extension words are skipped. Single frame fields can be skipped with `--ignore frame.addr,frame.stagec,...`. **Retry test** (`retrymoira`, 68030/68040/LC040): Faults every bus access of an instruction, lets a handler execute `rte` and checks that the retried instruction leaves the same registers, memory, PC and SR as an undisturbed run. Needs no reference core. All models from the 68020 up are tested. Moira restarts a faulted instruction on all of them. In UAE mode the 68020 hands the registers as they were at the time of the fault to the handler (as UAE does) and rolls them back in RTE if the handler leaves the frame untouched. Cases that raise an exception themselves, touch the exception frame or the vector, or fault in the middle of a long write are skipped. |
| `Sequence/` | `sequenceuae`, `sequencemame` | Differential test of the interrupt machinery. Generates random programs (`--programs <n>`, `--seed <n>`) that mix ordinary instructions with `stop`, `rte`, `trap`, `chk`, trace mode and changing interrupt levels, and runs them on Moira and on WinUAE's 68000/68010 core in lockstep. After every instruction the registers, SR, stack pointers, stopped state, pending exceptions and written memory are compared. Covers IPL sampling, level 7 edge triggering, trace, STOP wake-up and RTE sequencing. Programs that end in an address error are not compared (UAE's 68010 frames are unreliable). `--cpu 68020` and `--cpu 68030` run the same programs on UAE's 68020 and 68030 cores (format 2 frames for trace, CHK, TRAPV and division by zero, the 68010+ RTE with a format word). Both reach 100% and are part of ctest (`SequenceUAE020`, `SequenceUAE030`). The status register values of those models contain no M bit and no T0 bit unless asked for: `--master` generates the M bit (15 of 1000 programs differ: an RTE to user mode with T1 and M both set makes UAE trace immediately, Moira after the next instruction; probably a UAE quirk) and `--t0` generates trace on change of flow (ctest: `SequenceUAE020T0`, `SequenceUAE030T0`, 99.5% required). Moira traces taken branches, JMP, JSR, BSR, DBcc, RTS, RTR, RTD, RTM, RTE, TRAP, TRAPV, CHK, division by zero and ORI/ANDI/EORI to CCR and SR, MOVE to SR, all when T0 (and not T1) was set before the instruction. Programs with T0 contain these instructions but no STOP: UAE traces a STOP that changes the T0, S or M bit, which contradicts the comment in its own source. About 0.2% of the programs differ because UAE does not trace an RTE that leaves T0, S and M unchanged; Moira traces every RTE. Malformed PMMU opcodes (coprocessor 0) are left out on the 68030 and later because Moira raises the illegal instruction exception and UAE the line F exception. `--cpu 68040` works but is not part of the automated runs: UAE takes no trace exception after TRAP, TRAPV and a CHK that traps, and CHK leaves different condition codes. Which core is right is not known. `sequenceuae` compares Moira's UAE mode with WinUAE's 68000 and 68010 cores. `sequencemame` compares Moira's MAME mode with MAME's microcoded 68000 (no 68010). A program ends early when MAME runs into one of its known defects: it loses the interrupt level if a trace exception and an interrupt are due together, and a STOP instruction takes an interrupt that the newly loaded mask blocks. About 20% of the programs end that way. Options: `--cpu 68000|68010`, `--min <percent>` (required match rate, used by ctest), `--program <n>`, `-v <n>`. Takes a few seconds. |
| `Random/` | `randomuae`, `randommusashi`, `randommame`, `dasmmot`, `dasmmit` | Runs randomized instructions on Moira and on a reference core (UAE, Musashi or MAME; MAME covers the 68000 only and skips address errors, which `exceptionmame` covers) and compares registers, memory and cycles. A complete run takes about an hour per reference. The reference cores sit behind the `Reference` facade (`Random/Reference.h`), which also holds the known differences that are tolerated per reference. The seed is derived from the date unless `--seed <n>` is given. **Disassembler tests** (`dasmmot`, `dasmmit`, built from the same sources, same options): Disassembler tests. Every opcode is disassembled by Moira in several syntaxes and compared with reference disassemblers. `dasmmot` (Motorola syntax) compares `Syntax::GNU` with Binutils, `Syntax::MUSASHI` with Musashi and `Syntax::UAE` with UAE. `dasmmit` (MIT syntax) compares `Syntax::GNU_MIT` with a Binutils that is compiled without `MOTOROLA`. Moira's own syntaxes (`MOIRA`, `MOIRA_MIT`) have no reference and are only checked for plausible output. |
| `Common/` | (sources) | Code shared by all tools (`Common.h/.cpp`: banner, command line parser, progress dots, random numbers) and the SingleStepTests file reader. |
| `CpuTester/` | (none) | Test images (ADF and HDF) that have been created with Toni Wilen's cputester. They run inside an Amiga emulator and are not part of the build. |
| `ThirdParty/` | (libraries) | Code and data from other projects that is only used by the tests: UAE, Musashi, MAME's 68000, Binutils, the glue code, and the SingleStepTests data. See the license files in the individual folders. |

## Running the tests

```
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j8
./build/Tests/Smoke/smoke
./build/Tests/Random/randomuae --cpu 68000
ctest --test-dir build
ctest --test-dir build -L smoke      # only the tests with a label (unit, smoke, sst, random, exception, dasm)
```

The random runners, the disassembler tests and the exception tests accept `--help`. The automated random and disassembler runs use a fixed seed (`--seed 1`) so that they are reproducible.

`unit` accepts the usual doctest options, e.g. `-ts="MMU"` runs a single
test suite, `-ltc` lists all test cases, and `-tce="*UAE*"` skips the
comparison with UAE. The comparison can be tuned with the environment variables
`FPUREF_ITERATIONS`, `FPUREF_SEED`, `FPUREF_CLEAN` and `FPUREF_MAXPRINT`.

`smoke` is linked against a special build of Moira that mimics MAME
(`moiraMAME`), because MAME's expected results differ from the real hardware in
a few places. The random runners are linked against builds that mimic UAE
and Musashi, respectively.
